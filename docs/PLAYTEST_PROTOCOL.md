# 真实设备与真人试玩验收协议

本协议用于补齐自动化测试无法证明的可用性证据。执行前记录候选 commit SHA、设备、操作系统、浏览器和屏幕尺寸；不得把模拟存储或 CI 截图写成真实手机验收。

## 1. 环境记录

每轮测试记录：

- Candidate commit：
- 日期 / 时区：
- 设备型号：
- 操作系统及版本：
- 浏览器及完整版本：
- 屏幕分辨率、缩放和方向：
- 是否首次启动 / 是否清理站点数据：
- 测试者是否第一次玩本游戏：
- 录屏或截图证据位置：

建议最低组合：
- Android 真机：Chrome，竖屏与横屏各一轮。
- 桌面：Chrome 或 Edge。
- 第二浏览器引擎：Firefox（桌面）或 Safari（iOS，若可用）。

## 2. 全局检查

1. 清除站点数据，首次打开 `index.html`，确认从第一关开始。
2. 检查首屏标题、关卡目标和下一步操作是否清楚；不依赖开发者口头解释。
3. 检查所有关键按钮可见、可点击、触控目标不重叠，页面无横向滚动。
4. 切换竖屏/横屏、改变窗口宽度，检查场景图、操作面板和底部工具栏。
5. 检查浏览器控制台无未捕获错误；网络面板确认游戏运行不依赖第三方 CDN。
6. 检查键盘焦点可见、按钮有可读名称；开启系统减少动态效果设置，确认动画不会妨碍操作。

## 3. 六关验收

### 第一关：最后一盏灯

- 观察电源 A、B 的输入变化和主灯、应急灯反馈。
- 按目标真值表交换逻辑模块，完成主灯和应急灯修复。
- 验证只有正确逻辑才允许通过；错误模块不应误报成功。
- 记录玩家是否能理解“主灯需两路、应急灯任一路”的规则。

### 第二关：沉默的气闸

- 尝试在内门打开时启动均压，必须被拒绝。
- 关闭内门后执行均压。
- 尝试使用错误逻辑打开外门，必须被拒绝。
- 安装 AND 联锁后完成通行。
- 使用撤销、重置、刷新，检查状态与进度恢复。

### 第三关：失控的机械臂

- 不看开发说明，按分步教程完成七个动作：夹取、升高、平移、下降、释放、升高、归位。
- 检查教程高亮是否准确指向可操作热点；未激活热点不得偷偷加入程序。
- 检查执行时夹爪升降、货箱移动和小车平移是否清楚可见。
- 测试撤销、重置、刷新恢复。
- 特别检查手机上场景图缩放后，热点仍容易点击，且不会被教程卡片遮挡。

### 第四关：消失的一纳秒

- 观察原始电路是否能复现瞬态毛刺。
- 添加 BC 共识项，验证双向输入变化。
- 运行传播延迟扰动检查，确认界面报告 54/54，而不是只显示“通过”却没有测试数量。
- 测试撤销和刷新恢复。

### 第五关：三重备份

- 在高、低两种工况分别标定三路传感器。
- 定位反相故障通道；尝试隔离健康通道，验证不能通过。
- 隔离故障通道，恢复双通道一致性并验证。
- 检查读数、故障提示和最终结果在窄屏上仍可读。

### 第六关：最后的求救

- 从干净存档完成全部前置关卡，不注入预设完成状态。
- 验证冗余电源真值表、机械臂安全顺序、气闸复核、传感器双通道复核。
- 验证天线互锁；未满足前置条件时不得放行。
- 检查时序毛刺证据和 54 组延迟扰动结果。
- 分别执行 SOS 发射和地面站 ACK，确认发射成功不会自动伪造 ACK。
- 测试撤销、重置和刷新恢复。

## 4. 存档与恢复

每关至少执行：
1. 做出一个有效操作。
2. 切换离开关卡，再返回。
3. 刷新页面并重新打开。
4. 执行撤销，再执行重置。
5. 在浏览器禁用存储或模拟存储空间不足时尝试操作。

通过标准：正常存储时状态可恢复；存储失败时明确提示，当前会话不崩溃；不得显示“已保存”但实际丢失进度。

## 5. 失败判定

以下任一情况均记为失败并附证据：

- 页面崩溃、白屏、未捕获异常或关键按钮失效。
- 横向溢出、按钮重叠、文字被遮挡、触控热点不可达。
- 关卡未满足逻辑/安全条件却允许通关。
- 撤销、重置、关卡切换或刷新造成不合理状态、错误解锁或进度丢失。
- 教程提示与当前可操作热点不一致。
- 视觉动画掩盖关键状态变化，或移动端无法辨认状态反馈。
- 页面宣称完成，但缺少对应的可观察证据。

## 6. 证据记录格式

每个问题建立一条记录：

| 字段 | 内容 |
|---|---|
| Case ID | 例如 OC-MOB-03 |
| Candidate SHA | 完整 commit SHA |
| 环境 | 设备、系统、浏览器、屏幕 |
| 前置状态 | 首次启动 / 存档 / 已完成关卡 |
| 操作步骤 | 可复现的最小步骤 |
| 预期结果 | 明确、可观察 |
| 实际结果 | 实际观察，不写推测 |
| 判定 | PASS / FAIL / BLOCKED |
| 证据 | 截图、录屏、控制台日志 |
| 严重度 | Blocker / Major / Minor |
| 复现次数 | 首次 / 3 次 / 多设备 |

不要将“未复现”写成“已修复”；需要在相同环境复测，并记录版本和次数。

## 7. 发布门槛

- 六关主流程在目标桌面浏览器完整通过。
- Android 真机竖屏、横屏均无阻塞级问题。
- 至少一台桌面设备完成全流程。
- 关键存档和安全拒绝路径均有实际证据。
- 至少两名首次接触游戏的测试者能在不接受口头提示的情况下完成第一、二关，并记录卡点。
- 所有 Blocker 清零；Major 问题要么修复并复测，要么明确从首发范围移除。
