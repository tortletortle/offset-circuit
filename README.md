# 错位电路 / OFFSET CIRCUIT

离线优先的逻辑电路解谜游戏。游戏主体为单文件 `index.html`，不依赖远程脚本、API 或在线服务。

## 运行游戏

直接用现代桌面或移动浏览器打开 `index.html`。首次进入从第一关开始；完成前三关后解锁第四关，完成第四关后解锁第五关，完成第五关后解锁最终任务。工作台原有六个逻辑门修复关卡、随机挑战、故障诊断和门延迟实验室仍保留。

## 剧情关卡

- **第一关：最后一盏灯** — 观察主灯与应急灯的供电现象，检修错位的逻辑模块。
- **第二关：沉默的气闸** — 关闭内门、降低舱压并修复开门联锁。错误操作会被独立安全条件拦截，不会扣分或强制重开。
- **第三关：失控的机械臂** — 通过点按指令编排夹取、升高、平移、下降、释放和归位的顺序；逐步执行，违反安全互锁的动作会被拦截。
- **第四关：消失的一纳秒** — 用事件驱动时序仿真复现竞争冒险，安装 BC 共识通路，并通过双向输入与传播延迟扰动验证。
- **第五关：三重备份** — 对三路压力传感器执行高、低两种工况标定，定位反相故障通道，再隔离异常通道并恢复双通道一致性。
- **第六关：最后的求救** — 综合修复冗余供电逻辑、执行机械臂安全状态机、明确复核第二关气闸联锁与第五关压力双通道、部署并锁定通信天线，消除握手毛刺并通过 54 组传播延迟扰动验证；SOS 发射后还必须收到独立的地面站 ACK。

第二关采用离散状态模型：气压只有“正常/已均衡”两个状态，不模拟真实气体流动、压力变化时间或工程级气闸控制。第三关采用有限状态动作模型，不模拟真实机器人动力学、碰撞或伺服控制。第四关使用离散门延迟和 transport 事件模型，是数字逻辑教学抽象，不是芯片级 SPICE 或晶体管级时序签核。第五关使用固定的二值传感器故障模型，不模拟真实模拟传感器噪声、漂移或现场安全认证。第六关将前述知识整合为确定性的任务状态机：能源逻辑采用四组真值测试，必须显式复核第二关气闸与第五关双通道完成状态，时序修复记录实际毛刺宽度并要求 54 组扰动全部通过；SOS 发射与地面站 ACK 是两个独立状态。不模拟真实航天器动力学、射频链路、轨道通信、真实接收窗口倒计时或硬件安全认证。场景均为游戏化抽象，不应作为现实安全控制参考。

## 进度与恢复

- 第一关草稿、第二关状态、第三关程序、第四关诊断状态、第五关标定记录和第六关最终任务进度使用独立的浏览器存储键；第六关状态升级为 v2。
- 剧情关的成功操作、撤销和重置可恢复；存储被禁用或空间不足时会显示提示，但当前会话仍可继续。
- 清除浏览器站点数据会删除本地进度。当前没有云同步。

## 自动化质量检查

需要 Node.js 20+。在项目目录运行：

```sh
npm install
npx playwright install --with-deps chromium
npm test
```

测试包括：
- 气闸安全状态机、错误操作拦截和正确通关路线；
- 机械臂有限状态机、全部可达状态不变量和正确搬运路线；
- 时序仿真复现 5 ns 瞬态低脉冲、共识项消除双向毛刺，以及 54 组传播延迟扰动；
- 三重备份的两工况传感器故障定位、错误隔离拒绝、双通道一致性及完成状态校验；
- 最终任务的四组冗余电源真值测试、机械臂顺序互锁、真实前置关卡状态复核、天线互锁、实测毛刺宽度、54 组时序扰动、SOS 发射与独立 ACK 门禁；
- HTML 元素 ID 唯一性、内嵌脚本语法、离线依赖和响应式样式；
- Chromium 中第一关真实真值表修复与解锁衔接、后续剧情操作、撤销/重置、刷新恢复、存储损坏/写入失败处理、机械臂实际位移与升降、第五关的标定/隔离/验证/存档、第六关完整剧情联调、发送/ACK 分离、撤销/恢复与手机视口横向溢出检查。

GitHub Actions 使用固定的 Ubuntu 24.04 + Chromium 环境，避免 `ubuntu-latest` 漂移造成 Playwright 不兼容。
