# 错位电路 / OFFSET CIRCUIT

[English](README.en.md)

离线优先的逻辑电路解谜游戏。游戏主体为单文件 `index.html`，不依赖远程脚本、API 或在线服务。

## 运行游戏

直接用现代桌面或移动浏览器打开 `index.html`。首次进入从第一关开始；完成前三关后解锁第四关，完成第四关后解锁第五关，完成第五关后解锁最终任务。工作台原有六个逻辑门修复关卡、随机挑战、故障诊断和门延迟实验室仍保留。

## 剧情关卡

- **第一关：最后一盏灯** — 观察主灯与应急灯的供电现象，检修错位的逻辑模块。
- **第二关：沉默的气闸** — 关闭内门、降低舱压并修复开门联锁。错误操作会被独立安全条件拦截，不会扣分或强制重开。
- **第三关：失控的机械臂** — 通过场景热点和分步教程编排夹取、升高、平移、下降、释放和归位的顺序；违反安全互锁的动作会被拦截。
- **第四关：消失的一纳秒** — 用事件驱动时序仿真复现竞争冒险，安装 BC 共识通路，并通过双向输入与传播延迟扰动验证。
- **第五关：三重备份** — 对三路压力传感器执行高、低两种工况标定，定位反相故障通道，再隔离异常通道并恢复双通道一致性。
- **第六关：最后的求救** — 综合修复冗余供电逻辑、执行机械臂安全状态机、明确复核第二关气闸联锁与第五关压力双通道、部署并锁定通信天线，消除握手毛刺并通过 54 组传播延迟扰动验证；SOS 发射后还必须收到独立的地面站 ACK。

第二关采用离散状态模型：气压只有“正常/已均衡”两个状态，不模拟真实气体流动、压力变化时间或工程级气闸控制。第三关采用有限状态动作模型，不模拟真实机器人动力学、碰撞或伺服控制。第四关使用离散门延迟和 transport 事件模型，是数字逻辑教学抽象，不是芯片级 SPICE 或晶体管级时序签核。第五关使用固定的二值传感器故障模型，不模拟真实模拟传感器噪声、漂移或现场安全认证。第六关是确定性的教学任务状态机，不模拟真实航天器动力学、射频链路、轨道通信或硬件安全认证。所有场景均为游戏化抽象，不应作为现实安全控制参考。

## 进度与恢复

- 各剧情关卡的草稿、状态、程序和诊断记录使用独立的浏览器存储键。
- 剧情关的成功操作、撤销和重置可恢复；存储被禁用或空间不足时会显示提示，但当前会话仍可继续。
- 清除浏览器站点数据会删除本地进度。当前没有云同步。

## 自动化质量检查

需要 Node.js 20+。在项目目录运行：

```sh
npm install
npx playwright install --with-deps chromium
npm test
```

测试覆盖气闸、机械臂、时序、传感器和最终任务状态机，真值表、状态不变量、六关完整流程、撤销/重置、刷新恢复、损坏/不可用存储、移动视口及浏览器交互。GitHub Actions 在 Ubuntu 24.04、Node.js 22 和 Chromium 环境中运行回归测试。
